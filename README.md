# vzlyot.post — Инструкция по запуску

Полная пошаговая инструкция, как развернуть систему с нуля.
Идём по порядку, ничего не пропускаем.

---

## Быстрый запуск на своём компьютере (без Railway)

Нужен только [Node.js](https://nodejs.org). PostgreSQL ставить не надо — он встроен.

1. Дважды щёлкни **«Запустить кассу.bat»** в корне проекта.
2. Первый раз он сам скачает пакеты и создаст базу с demo-данными (пару минут).
3. Откроется касса: `http://localhost:3000/app` — вход `demo@vzlyot.post` / `demo1234`, PIN `1111`.
   Сайт с регистрацией — `http://localhost:3000`.
4. Ключ для админки (`/admin.html`) напечатан в окне запуска.
5. Остановить — **Ctrl+C** в окне (так база выключается аккуратно).

База и секреты лежат в `local/data/` (в git не попадают). Удалишь эту папку — база создастся заново.
Работает только на этом компьютере: с телефона или другого ПК касса не откроется.

## Страницы

| Адрес | Что это |
|---|---|
| `/` | Сайт (лендинг) с регистрацией по номеру телефона — `backend/public/index.html` |
| `/app` | Касса — `backend/public/app.html` |
| `/admin.html` | Ваша админ-панель (вход по `ADMIN_KEY`) |

## Тарифы и цены

Всё задаётся в одном файле — `backend/config/plans.js`: названия, **цены** и что входит в тариф.
Сайт, касса и админка берут данные оттуда.

- **Старт — 300 000 сум/мес** — касса, меню, смены, сотрудники с PIN, выручка, поштучный склад. Блюда продаются без техкарт.
- **Бизнес — 479 000 сум/мес** — дополнительно техкарты, склад по граммам и литрам, финансы (расходы, прибыль), клиенты и бонусы.
- **Сеть — цена договорная** (`price: null`) — как «Бизнес»; несколько точек пока не реализованы.

Новый клиент после регистрации получает 14 дней на «Старте». Тариф меняется в админ-панели;
касса подхватывает его при следующем открытии, данные сохраняются.

## Админ-панель (`/admin.html`)

- **Клиенты**: подписка, срок доступа, пользуется ли кассой (последняя продажа, заказы за 7 дней,
  оборот за 30 дней), сколько оплатил. Сверху — фильтры: платят, пробный период, скоро закончится,
  истекли, не пользуются, заблокированы.
- **Карточка клиента** (нажать на строку): записать оплату и сразу продлить доступ, сменить тариф и дату,
  изменить данные и заметку, задать новый пароль, заблокировать, график заказов по дням,
  **«Открыть кассу клиента»** — касса открывается только для просмотра (на 1 час, изменить ничего нельзя).
- **Оплаты**: все записанные оплаты и суммы по месяцам в долларах и сумах.

Оплаты записываются вручную: вы получили деньги (Click, Payme, наличные) — внесли запись.

## Шаг 1. GitHub — создаём репозиторий

1. Заходишь на github.com → New repository
2. Название: `vzlyot.post`
3. Private (чтобы код был скрыт от посторонних)
4. Создаёшь

Затем у себя на компьютере (или прямо здесь, в Claude):

```bash
cd vzlyot.post
git init
git add .
git commit -m "Первый коммит: backend + frontend"
git branch -M main
git remote add origin https://github.com/ТВОЙ_АККАУНТ/vzlyot.post.git

```

1. В проекте Railway: New → Database → Add PostgreSQL
2. Railway автоматически создаст переменную `DATABASE_URL` и подключит её к твоему сервису

## Шаг 4. Переменные окружения

В настройках сервиса (Variables) добавь:

| Переменная | Значение |
|---|---|
| `JWT_SECRET` | любая длинная случайная строка, например `kj3h4kjh5b34kjhb5kj34hb` |
| `ADMIN_KEY` | свой секретный пароль для админки, например `MySecretAdmin2025!` |
| `PORT` | `3000` (Railway может переопределить сама) |

`DATABASE_URL` уже будет добавлена автоматически шагом выше.

## Шаг 5. Инициализация базы данных

Таблицы и обновления базы применяются **сами при каждом запуске сервера**
(`db/migrate.js`: `schema.sql` + файлы из `db/migrations/`, затем шифрование PIN).

Demo-данные нужно создать один раз вручную. В Railway: открой вкладку сервиса → Settings → найди "Run command" или используй Railway CLI:

```bash
railway run npm run init-db
```

Это создаст demo-аккаунт:
- Email: `demo@vzlyot.post`
- Пароль: `demo1234`
- PIN: `1111` (владелец), `2222` (админ), `3333` (кассир)

## PIN-коды сотрудников

- PIN хранится в базе только в зашифрованном виде (bcrypt), в ответах API его нет.
- PIN — ровно 4 цифры и не может совпадать с PIN другого сотрудника той же точки.
- При регистрации владелец получает случайный PIN — касса показывает его один раз в приветствии сразу после регистрации. Общего «0000» больше нет.
- Забыл PIN или первый вход — на экране PIN ссылка **«Владелец: задать или сбросить PIN»** (нужны номер телефона или email и пароль владельца, `POST /auth/owner-pin`).
- Владелец забыл **пароль** — задайте новый в админ-панели (карточка клиента → «Новый пароль»).

## Время в отчётах

«Сегодня», «вчера», неделя, месяц и т.д. считаются по Ташкенту (`utils/time.js`), а не по UTC сервера.

## Как активировать клиента (твоя ежедневная задача)

Когда новый клиент регистрируется через лендинг — он попадает в таблицу `accounts` со статусом `trial` (14 дней бесплатно).

Проще всего всё делать в админ-панели (`/admin.html`, раздел выше). То же самое можно сделать запросом (Postman или curl):

```bash
curl -X POST https://твой-сервер.up.railway.app/admin/accounts/5/activate \
  -H "x-admin-key: ТВОЙ_ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"plan":"business","months":1}'
```

Где `5` — это ID аккаунта клиента (узнать через `/admin/accounts`).

**Посмотреть всех клиентов:**
```bash
curl https://твой-сервер.up.railway.app/admin/accounts \
  -H "x-admin-key: ТВОЙ_ADMIN_KEY"
```

**Продлить подписку:**
```bash
curl -X POST https://твой-сервер.up.railway.app/admin/accounts/5/extend \
  -H "x-admin-key: ТВОЙ_ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"months":1}'
```

**Заблокировать (если не оплатил):**
```bash
curl -X POST https://твой-сервер.up.railway.app/admin/accounts/5/block \
  -H "x-admin-key: ТВОЙ_ADMIN_KEY"
```

## Как работает подписка клиента — логика

1. Клиент регистрируется → `status = 'trial'`, `expires_at = +14 дней`
2. Все запросы к API проходят через `middleware/auth.js`
3. Если `expires_at` в прошлом → сервер возвращает `402 SUBSCRIPTION_EXPIRED`
4. Фронтенд показывает экран "Подписка истекла, продлите тариф"
5. Ты получаешь оплату (вручную, через Click/Payme/наличные)
6. Вызываешь `/admin/accounts/:id/activate` — клиент снова работает

Всё просто: одна таблица `accounts`, одно поле `expires_at`, одна проверка в middleware.
